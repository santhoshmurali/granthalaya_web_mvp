# Development and Testing
## VERY IMPORTANT
- Be Simple, Apprach Tasks in a simple, Incremental way.
- Complex Tasks also to be broken down to simple tasks.
- Work Incrementally ALWAYS. Small, Simple Steps. Validate Each Step Individully and Incrementally before moving on.
- USE LATEST APIS AS OF NOW.
## IMPORTANT & MANDITORY
- Internal Task Tracker : Create/Update a at the Tasktrackr.md root of the project folder and add this to .getignore  
- At the beginig of every session Track and Capture Major Milestone to be acomplished and update the Status under Session Name/Time.

# Coding Style
## VERY IMPORTANT
- Do not overengineer. Do not program defensively. Use exception managers only when needed.
- Work Incrementally in smnall steps, validate each step.
- Identify root cause before fixing things. Prove with Evidence, then fix and prove the fix.
- Favor clear, consise docstring comments. Be sparing with comments outside docstrings.
- Favor Short modules, short methods and functions. Name things clearly.
- VARIABLE and CONSTANT names should be easily understandable.
- No Emojies in code to print statments. 

# Platforms
## VERY IMPORTANT
- Use the latest Library APIs
- Use `uv` as python package manager. Always `uv run xxx` never `python2 xxx` or `python xxx`, always `uv add xxx` never `pip install xxx`
- For a new Project if `uv` is not initated, then run `uv init` and followed by `uv venv`.
## IMPORTANT
- Enforce End to End Testing and Code Review before `git commit`, if not already done.


# Debugging and Fixing
## VERY IMPORTANT
- When troubleshooting problems, Always Identify root casue BEFORE fixing it.
- If the root caue for any issue is a Known Issue or Liibrary Version compatability, challenege it with devils adovcate before finializing it.
- PROVE THE PROBLEM FIRST, don't giess it.
## IMPORTANT
- Try One test at a time. Be Methodical.
- Reproduce consistently.
- Don't jump to Conclusions.
- Don't apply workarounds.

# Documentation
## VERY IMPORTANT
- If a Project is initiated without "Docs" directory, create one and add "Readme.md" and "help.md"
- Keep "Readme.md" & "help.md" concise and clean up old files.
- Update "Readme.md" whenever a major milestone is accomplishe/modified and tested ok.
- Update "help.md" with Tutorials and Steps whenever new milestone is acheived/modified and tested ok. 
- When solving complex problem during debugging process, update lesson learnt section in docs directory.
